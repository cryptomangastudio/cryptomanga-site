# カクヨム用の記法と表記

カクヨムに投稿する前提で、本文の書式と数字の書き方を決める。**サイトの仕様は変わるので、迷ったら公式ヘルプ「ルビや傍点を付ける(カクヨム記法を使う)」と、エディタの「記法と整形」を確認する。**この資料のうち「公式で確認済み」とあるもの以外は、一般的な慣行か非公式の情報。

## 1. ルビ(公式ヘルプで確認済み)

| 親文字 | 書き方 | 例 |
|---|---|---|
| 漢字だけ | 直後に《》でルビ | `赤字《あかじ》` |
| 漢字以外(かな・カタカナ・記号)を含む | 親文字の直前に縦棒｜を置き、直後に《》 | `｜ゲラ《げら》`、`｜青い鳥《ブルーバード》` |
| 《 を文字として出したい | 直前に縦棒｜ | `｜《` |

- 縦棒は全角(｜)でも半角(|)でも使える。
- 漢字だけでも、熟語の途中から始めたいときは縦棒で始点を指定できる。
- **ルビを振る基準**(読みやすさ):初めて出る難読語・固有名詞・造語にだけ、初出に1回。同じ語に毎回振らない。常用漢字で読めるものには振らない。
- ルビは読みの補助であって、意味の説明に使うのは最終手段(`漢字《別の語》`のような当て字は、使うなら作品全体で方針を決める)。
- 一語に長いルビを付けると、行間が崩れる。長いときは、本文の側で言い換える。

## 2. 傍点(強調)

- エディタの「記法と整形」の「傍点」ボタンを使うのが確実。選択した文字に記法が入る。
- 手で書く場合は `《《強調したい語》》` の二重山括弧が一般に知られているが、公式ヘルプの傍点の項で確認してから使う。
- 縦棒の直後に置くと傍点にならない(エスケープされる)ことがある、という報告がある。
- 傍点は、1話に数回まで。**強調を傍点に頼ると声が弱く見える**。強調したいことは、語順・文の短さ・改行で作る。

## 3. 記号

| 項目 | 書き方 |
|---|---|
| 三点リーダ | 「……」(2つ重ねる)。「...」「・・・」「…」(1つ)にしない |
| ダッシュ | 「――」か「——」(2つ重ねる)。作品内で統一。「ー」(長音)を代用しない |
| 感嘆符・疑問符 | 全角の「！」「？」。後ろに文が続くときは全角スペースを1つ空ける(「えっ！？　今なんと」)。「」を閉じる直前は空けない |
| 括弧内の句点 | 「」の最後に句点を打たない(`「行く」`) |
| 句読点 | 「、」「。」。半角の「,」「.」を混ぜない |
| 場面転換 | 空行を1行。または「＊」「◇」の1行(作品内で統一)。「---」は使わない(他の用途と紛れる) |

## 4. 数字の書き方

カクヨムは横書きが標準で、閲覧設定で縦書き表示を選べる(要確認)。縦書きにも対応できるように、**漢数字を基調**にする。

### 基本方針

1. **作品内で統一する。**漢数字と算用数字を場面によって混ぜない。
2. **2桁までの数、日付、時刻、年齢、回数、順序は漢数字。**(`十一月六日`、`午前十一時`、`二十九歳`、`三度`、`一枚目`)
3. **3桁以上の数は、漢数字だと読みにくい。**(`三百二十一枚`)次のどれかにする。
   - 概数にぼかす(`三百枚ほど`)
   - 書く必要がなければ「何百枚もの」「束」にする
   - どうしても正確な数が必要なら、そこだけ算用数字(`321枚`)にして、作品内の方針を決める
4. **年号は位取りなしの漢数字**(`二〇二六年`)か、西暦を出さずに「あの年」とする。
5. **慣用句・熟語は漢数字**(`一人`、`二つ`、`三日坊主`、`十分`)。
6. **半角の英数字は混ぜない。**固有の表記が必要なとき(`SNS`)だけ、全角にするか、作品内で統一する。
7. **「一」と長音「ー」、「〇」(ゼロ)と「○」(丸)を取り違えない。**

### 読みやすさ

- 漢数字は、桁が増えると文字が詰まって読みにくい。**数字は物語に必要なときだけ出す。**正確な数が要る場面(犯人の数え間違い、金額、日数の矛盾が手がかり)は、数字そのものが小説の仕掛けになるので、読みやすさより優先する。
- 数字が3つ以上並ぶ文(`十一月二日。今日が六日だから、四日前。`)は、読点・句点で区切って、一度に頭に入れる数を2つ以内にする。
- スマホの狭い画面では、数字の途中で折り返されることがある。投稿前に**スマホ表示でプレビュー**する。

## 5. 書式

| 項目 | 方針 |
|---|---|
| 字下げ | 段落頭の字下げは、する/しないを作品内で統一する。カクヨムのWeb読みでは、字下げなしで空行を入れる作品も多い。書籍化を意識するなら字下げする |
| 空行 | 段落の間の空行は、入れる/入れないを統一。連続する空行(3行以上)は、スマホで大きな空白になる |
| 段落 | スマホでは長い段落が壁になる。3〜5行を目安に区切る。決定的な一文は一行段落にしてよい |
| 台詞 | 台詞の前後に空行を入れると読みやすい。地の文が痩せないように、台詞のあいだに動作や間を挟む |
| 1話の長さ | 公式の上限表記は見当たらない。非公式の情報では、2,000〜5,000字程度が多い(リワードの仕組みと関連づける見方もあるが、根拠は未確認) |

## 6. 作品情報(カクヨムの入力欄)

作品タイトル、キャッチコピー、あらすじ、タグ、カテゴリの文字数や個数の**上限は、公式の入力画面で確認する**(今回の調査では確認できなかった)。

- **タイトル**:内容がわかり、声が出ているもの。説明が足りないと、一覧でクリックされにくい。
- **キャッチコピー**:一行で、問いか違和感を渡す。
- **あらすじ**:冒頭の本文を貼らない。「誰が、何に出会い、何が問題になるか」を数行で。ネタバレしない。
- **タグ**:作品の型・ジャンルを、読者が検索する語で。

## 7. 投稿前チェック

```bash
python3 .claude/skills/first-person-novel/scripts/kakuyomu_check.py 原稿.md
```

ルビの記法ミス(縦棒の抜け、孤立した《》)、「...」やダッシュの表記、半角の！？、括弧内の句点、数字の混在と長い漢数字、字下げの混在、連続する空行、本文の文字数(ルビ除く)を調べる。設計メモが同じファイルにある場合は `--skip-header` を付ける。

このスクリプトは公式の検証ではない。最後は、カクヨムのプレビューで、スマホと縦書き表示を実際に見る。
