# 設定の保持と破綻防止

AIに長めの小説を書かせると、設定を無視する、前の話と矛盾する、途中から別人になる、という破綻がよく起きる。原因を知らずに「設定を守って」と頼んでも直らない。**仕組みで防ぐ。**

## なぜ破綻するか

| # | 原因 | 典型的な症状 |
|---|---|---|
| C1 | 設定が文脈にない(新しいセッション、会話の圧縮で消える) | 前回決めた呼び方・世界のルールがなかったことになる |
| C2 | 設定が長文に埋もれ、書いている最中は直近の文に注意が引っ張られる | 設定の最初の方は守るが、後半の項目を忘れる |
| C3 | 平均への回帰:生成は「ありがちな人物・展開」へ引き寄せられる | 偏屈なはずの語り手が、いつのまにか素直で優しい標準人格になる。口調が丁寧で整ってくる |
| C4 | 局所最適:その場面を面白くするために過去の事実を曲げる | 便利な新設定、突然の能力、都合のいい知識、突然の過去の暴露 |
| C5 | 長尺での累積ドリフト | 名前の表記ゆれ、呼称の変化、年齢・日数・季節・怪我・持ち物・位置関係のずれ |
| C6 | 語り手の知識の漏れ(一人称で致命的) | 語り手が見ていない場面を知っている。他人の内心を断定する |
| C7 | 結末を急ぐ・伏線を取りこぼす | 回収されない伏線、突然の収束、設定の放置 |
| C8 | 修正の副作用 | 一箇所を直すと、別の場面と矛盾する |
| C9 | 能力・魔法・ルールのコストを忘れる | 制約があるはずの力が、後半で無制限に使われる |
| C10 | 「守りました」という自己申告 | 守っていないのに、守ったと報告する |

## 防ぎ方:設定を「正本」としてファイルに固定する

会話の記憶ではなくファイルを真実にする。作品フォルダ(`novels/<作品名>/`)に次を置く。

```
00_企画.md          ログライン・問い・冒頭の声と結末の声
01_語り手設計.md     設計シート(02_一人称の設計.md のテンプレ)
02_人物.md          人物ごとの 欲求/傷/口調/呼称/口癖/やらないこと
03_世界とルール.md   世界のルール、能力の代償、固有名詞の正しい表記
04_時系列.md        出来事の日付・曜日・経過日数・季節
05_知識マップ.md     誰が何をいつ知ったか(特に語り手が知っていること/知らないこと)
06_継続状態.md       怪我・持ち物・服装・金・居場所・関係の温度(話ごとに更新)
07_伏線台帳.md       張った伏線/回収予定話/回収済み
08_禁止事項.md       この作品でやらないこと
09_進捗メモ.md       どこまで書いたか、次に書くこと
canon.json          表記・禁止語・代名詞の機械チェック用(scripts/canon_check.py)
本文/第01話.md ...
```

規則:
- **本文と正本が食い違ったら、どちらかが誤り。**どちらを正にするか判断し、正本に記録してから本文を直す。黙って本文だけ変えない。
- 設定を変えるときは、先に正本に書き、理由と影響範囲(どの話に関係するか)を書く。
- セッションを開始したら、**最初に正本を読む**。前の会話に頼らない。

## 設定カード(15行以内)

正本は長い。毎回の執筆の冒頭に貼る、短縮版を作る。

```
■語り手:僕/二十九歳/校正者/回想型(十年後)/聞き手=亡き妹
■声:乾いた皮肉。比喩は仕事道具(赤ペン、ゲラ)から。感情を名指さない
■盲点:先輩の親切を「監視」と読んでいる(実は気遣い)
■絶対に守る:・語り手は妹の死の日を直接語らない(まだ)
              ・先輩のことは「先輩」と呼ぶ。名前で呼ぶのは最終章
              ・語り手が見ていない場面は書かない
■能力/ルール:(あれば。代償も)
■今の状態:季節=十一月/左手首を捻挫中/鞄に妹の万年筆
■知っていること:先輩が妹の同僚だったこと。知らないこと:先輩が妹の最後の電話を受けたこと
■やらないこと:偶然の再会を使わない/説明の台詞を書かない/章末で予告しない
```

## 書く前(プレフライト)

1. 設定カードと、直前の話の末尾を読む。
2. その場面の**開始状態**を書く:いつ(日付・曜日・時刻・季節)、どこ、誰がいる、語り手の身体状態・持ち物・服装・感情の温度、語り手が今知っていること。
3. その場面で**足したくなる新事実**を先に列挙する。既存の設定と衝突しないか確認する。便利な新設定を足すときは、伏線として前の話に仕込めるか、仕込めないなら足さない。

## 書いた後(ポストフライト)

1. `scripts/canon_check.py` を回す(表記ゆれ・禁止語・代名詞)。
2. **照合表**を作る。設定カードの各項目について、本文の該当箇所を**引用**して守れているかを示す。引用できない項目は、守れていない可能性が高い。「守りました」だけの報告は受け付けない(C10)。
3. 継続状態(06)、知識マップ(05)、時系列(04)、伏線台帳(07)、進捗メモ(09)を更新する。
4. この話で追加した新事実を一覧にして、正本に追記する。

## 破綻チェック表(1話ごと)

| 項目 | 確認すること |
|---|---|
| 時間 | 前話からの経過日数。曜日・季節・昼夜が合うか。「昨日」「先週」が正しいか |
| 数 | 人数、金額、年齢、距離、日数が前と合うか |
| 場所 | 部屋の配置、移動手段と所要時間、誰がどこにいるか |
| 身体 | 怪我・病気・疲労・睡眠が引き継がれているか。治る速度が自然か |
| 持ち物・服装 | 前の場面で手放したものを持っていないか。着替えたか |
| 知識 | 語り手が知ったのはいつか。まだ知らないはずのことを知っていないか |
| 関係 | 呼び方、敬語の程度、距離感が前話から飛んでいないか |
| 口調 | 人物名を隠して台詞を読んで、誰かわかるか |
| 能力 | 代償、制限、回数、準備が守られているか |
| 動機 | 人物の行動が、その人の欲求と傷と矛盾しないか |
| 伏線 | 回収予定の伏線を忘れていないか。回収済みを再び使っていないか |
| 禁止事項 | 08_禁止事項.md に違反していないか |

## 長編を書くときの運用

- **1回の出力を短くする。**目安は一度に3,000〜5,000字(1話)。長尺を一括で書かせると、後半ほど設定がドリフトする。
- N話ごと(目安5話)に、**要約+状態**を作る(これまでの出来事・現在の継続状態・未回収の伏線・人物の関係)。古い本文を全部読み直す代わりに、要約と正本を読む。
- 前の話の文体を引き継ぐため、書き始める前に直前の話の**最後の1〜2段落**だけは読む。
- 設定の変更や、ユーザーからの方向転換があったら、正本を更新し、過去の話で影響を受ける箇所を列挙する。

## AIへの依頼の書き方(設定を守らせる)

- 設定は「守ってね」と言うより、**設定が破られるとどう困るか**を書く(「語り手は妹の死を直接語らない。語ると最終章の意味が消える」)。理由がある制約は破られにくい。
- 「設定に書いていないことを事実として足さない。足すなら『新設定』と明記して一覧にする」と指示する。
- 「設定と矛盾しそうなら、書く前に指摘して止まる」と指示する。
- 禁止事項は肯定形の指示と対にする(「偶然の再会を使わない。再会は語り手が自分から会いに行く形にする」)。
- 長い設定資料を貼るより、設定カード(15行)+必要な正本ファイルの参照を渡す。

## 人間の目が必要なところ

機械チェックでは見つからない破綻がある:人物が別人のように感じる、語り手の偏りが薄くなる、世界のルールが都合よく伸びる、感情の流れが唐突。数話ごとに、**人物名を隠した台詞テスト**と**声のテスト**(`02_一人称の設計.md`)をやり、ユーザーにも数話ごとに読んでもらう。
