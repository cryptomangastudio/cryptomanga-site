# 面白さのセルフチェック

「面白いか」を自分で判定するのは難しい。書いた本人(AIも)は、自分の文章を甘く採点する。以下の手順は、**甘い採点を防ぐ**ために作ってある。

## 前提:自己採点の限界

- 同じAIが書いて同じAIが採点すると、ほぼ全項目に高得点をつける。「良い点」を探す方向に偏る。
- 対策:(1)採点には**本文からの引用を必須**にする。(2)**悪い点を先に**探させる。(3)**別セッションの白紙の状態で読ませる**(冷読)。(4)最終判断は人間(ユーザー)が行う。
- 機械チェック(`fp_scan.py`、`canon_check.py`)に通ったことは「破綻していない」ことの証拠であって、「面白い」ことの証拠ではない。

## 手順

### Step 1:サンプルを書く

作品の最初の約2,000〜3,000字(冒頭)と、**最も大事な場面**(最大の転換点または感情の山)から約1,500字を書く。冒頭だけでは、中盤以降で面白さが保てるかわからない。

### Step 2:機械チェック

```bash
python3 .claude/skills/first-person-novel/scripts/fp_scan.py サンプル.md
python3 .claude/skills/first-person-novel/scripts/canon_check.py canon.json サンプル.md
```

### Step 3:7つのテスト(一つずつ、引用つきで答える)

1. **30秒テスト**:最初の300字を読んだ読者は、続きを読むか。冒頭で「声」「状況」「問い」のうち何が渡されているか。引用して答える。
2. **名前隠しテスト**:語り手の名前・性別・年齢を隠して、地の文3文だけで、この人だとわかるか。わかる根拠の語句を引用する。わからないなら、声がない。
3. **削除テスト**:段落を一つずつ削ってみて、物語が成立する段落はないか。成立する段落は、状況・関係・認識の何も変えていない。削除候補を最低3つ挙げる。
4. **反転テスト**:各場面の最初と最後で、何の値が反転したか。「希望→不安」のように書く。書けない場面は失敗。
5. **具体性テスト**:この作品にしか存在しない具体物(名詞・数字・手触り)を5つ引用する。5つ挙げられないなら、一般的な描写が多い。
6. **最後の一文テスト**:各場面・章の最後の一文を抜き出して並べる。総括・予告・格言で閉じていないか。具体的な一瞬か。
7. **次が気になるテスト**:読者の頭に開いている問いを全部書き出す。0個ならそこで読者は離れる。1個だけなら弱い。大きな問い・章の問い・場面の問いが重なっているのが理想。

### Step 4:採点(ルーブリック)

各項目 0〜3 点。**点数の根拠となる引用を必ず付ける。引用がない項目は0点。**

| 項目 | 0点 | 1点 | 2点 | 3点 |
|---|---|---|---|---|
| A. 問い | 開いている問いがない | 問いはあるが、ありふれている | 具体的で、先が気になる | 複数の問いが重なり、読み進めるほど増える |
| B. 声 | 誰が語っても同じ | 癖はあるが、一貫しない | 一貫した声があり、語り手が偏っている | 声そのものが読ませる。語り手の盲点が読者にだけ見える |
| C. 具体性 | 一般論・平均的な描写 | 具体物が散発的 | 具体物が場面を支えている | この作品にしかない具体物が、人物と感情を語っている |
| D. 反転 | 何も変わらない | 変化はあるが予想通り | 反転があり、納得できる | 反転が意外で、後で読み返すと伏線がある |
| E. 感情の真実 | 感情が説明され、整っている | 感情は描かれるが平均的 | 感情が行動に出ていて、少しずれている | 読者が「わかる」と思う、具体的でずれた感情がある |
| F. 緩急 | 一本調子 | 緩急はあるが機械的 | 緊張と弛緩、長短が使い分けられている | 緩みが山を高く見せている |
| G. 人間らしさ | AIっぽい癖が目立つ | 一部に残る | ほぼ気にならない | 偏りや無駄が自然に混ざっている |
| H. 設定の整合 | 破綻がある | 軽微な矛盾 | 整合している | 設定が物語を駆動している |

**合格の目安:**
- 合計 18点以上(24点満点)
- かつ、A・B・C・D のどれも2点以上
- かつ、0点の項目がない

これは自己採点なので、合格しても「面白い」とは限らない。Step 5・6 に進む。

### Step 5:弱点を探す(採点の甘さを補正)

次の質問に、**具体的に**答える。「特にない」は禁止。

- この文章を読んで退屈する読者は、どこで離れるか。何ページ目か。
- 同じジャンルの人気作と比べて、足りないのは何か。
- 作者が自分で気に入っている箇所のうち、読者にはどうでもいい箇所はどれか。
- 一番弱い段落を一つ選び、書き直す。書き直した版が元より良いなら、元の版が弱かったということ。他の箇所にも同じ処置をする。

### Step 6:冷読(別セッションで)

**書いたセッションとは別の、白紙のセッション**に、次を貼る(`プロンプト集.md` に貼り付け用あり)。

- 読者として読ませる。設計意図・設定・書き手の狙いは渡さない。
- 「どこで退屈したか」「どこで手が止まったか」「語り手を一言で言うと」「続きを読みたいか(理由)」「違和感のある箇所」「AIが書いたように感じる箇所とその根拠」を答えさせる。
- 冷読の答えと、Step 4 の自己採点がずれていたら、**冷読が正しいと考える**。ずれた箇所を直す。

### Step 7:人間(ユーザー)の判断

最終的に、ユーザーに次の質問で見てもらう。

- 続きを読みたいか。
- 一番好きな一文はどれか。(なければ、声が弱い)
- 一番つまらなかった箇所はどこか。
- この語り手を友達に説明するとしたら、何と言うか。

## 合格しなかった場合の直し方

| 弱い項目 | まず見直すもの |
|---|---|
| A. 問い | 冒頭の欲求と障害。伏せている情報と、その理由 |
| B. 声 | 設計シートの声の見本、語り手の偏り、目を留めるもの |
| C. 具体性 | 平均的な名詞を、この世界・この人物にしかない名詞に置き換える |
| D. 反転 | 場面の欲求。期待と結果のずれを作る |
| E. 感情の真実 | 感情を名指している文を消し、行動に置き換える。感情を遅らせる・ずらす |
| F. 緩急 | 長い内省を短くする。山の前に日常の一行を置く |
| G. 人間らしさ | `creative-writing/anti-ai-tells.md`、`06_失敗パターンと推敲.md` |
| H. 設定の整合 | `07_設定の保持と破綻防止.md` の照合表 |

直したら Step 2 からやり直す。2回直しても合格しないなら、設計(問い・欲求・語り手)に戻る。文章の直しでは解決しない。
