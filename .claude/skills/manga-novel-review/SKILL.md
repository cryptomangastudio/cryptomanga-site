# 提出前チェック(manga-novel-review)

ユーザーのコメント約110件から作った。シートの正本は、スプレッドシートの「査読チェックリスト」「継続性の表」「コメント台帳」の3タブ(スプレッドシートID 1m6otBwFxP8bULTt2XCgBT9YJql-RquNKj7ubKO0SRLg)。

## 手順

1. **設定を先に読む**:世界観、キャラ設定、継続性の表。設定にないことは足さない(足したいときは先に提案する)。
   **新しい場所を先に検知する**:プロットや字コンテの段階で、新しい場所(建物・部屋・屋外)が出てくる場合は、本文を書く前に、(a)実在の類例を調べ、(b)間取り図(画像)を作ってユーザーに見せ、(c)承認を得てから、世界観・継続性の表・日課表に書く。図には、出入口、人の動き、持ち物の置き場所を書き込む。
2. **書く/直す**。
3. **コメントは全件取得する**(返信済み・解決済みも含む)。最後の投稿がユーザーのものか、未解決のものを取りこぼさない。取得は `get_spreadsheet` の `commentsIncluded: true`。結果が大きいときはファイルに保存して python で絞る。
4. **修正後の本文を読み直す**。「直した」と言う前に、該当行を引用して確認する。
5. **他タブへの波及を直す**(`findReplace` の `allSheets`)。各話プロット、キャラ設定、課題シート、B列の「話の目的」、F列の備考。
6. **字数の上限を確認**:導入500/山場1000/山場2000は各1000/ヒキ500/合計3000以内(字コンテ)。小説はカクヨムで2,000〜5,000字が目安。
7. **機械チェック**(小説):`first-person-novel/scripts/fp_scan.py`、`kakuyomu_check.py`、`romance-fantasy/scripts/ai_tell_scan.py`。
   **変更箇所は紫で示す**:字コンテは、変更・追加したセル(C列)の文字を紫(#7B2FBF)にする。小説は、`scripts/diff_html.py 旧.md 新.md 出力.html` で、前の版から変えた文字を紫にしたHTMLを作り、Driveに `text/html` でアップロードして、Googleドキュメントに変換する(色が残る)。ユーザーが確認し終えたら、次の改稿の前に、字コンテの紫は黒に戻す。
8. **コメント台帳に追記**し、提出時に次の型で報告する:(1)直したこと(2)確認結果(引用つき)(3)まだ弱いところ(4)判断してほしいこと。

## チェック項目(要約。全文はシートのタブ)

- **A 設定照合**:時代考証、年齢と年数、人数の基準(ゼニア100人前後、ペニー30人)、聖女は無給、食事は朝夕、宿舎は大部屋。新設定を足さない。
- **B 時間・場所・在場**:場面ごとの時刻・場所・人物・持ち物。「また」「あのあと」「次の方」などの指示語の指す先。先出し場面が同じ場面の重複になっていないか。
- **C 台詞**:1台詞1話題、直前への返し、復唱・説明台詞・AIっぽさ、キャラ別の反応ルール(ゼニアは断らず否定語を使わない/ペニーは先に驚く反応役/サンクスは丁寧語でお願いの形)。
- **D 見せ方**:宣言した行為(治す、泣く、倒れる)に描写があるか。山の前後に余韻があるか。
- **E 小説化**:字コンテのト書きの朗読にしない。説明を動作に溶かす。身体感覚(五感・生理)。一人称の視点を守る(前世の記憶も「私」の主観)。文末の単調さ、定型比喩、物理的な矛盾(ポケットの位置、姿勢)。
- **F 修正の検証**:コメント全件、修正後の再読、他タブへの波及。行を書き換える時は、行番号がずれていないか、書く前に該当行を読んで確かめる(挿入・削除のあとは特に)。
- **H 新しい場所**:書き始める前に、新しい場所を検知し、実在の類例の調査と間取り図の承認を先に済ませる。
- **G 回答**:質問には結論と理由で答える。外部AIの指摘は、採否と理由を示す(誤りは棄却する)。

## 守ること

- 「直しました」は証拠にならない。**修正後の本文の引用**で示す。
- ユーザーが決めたこと(ゼニアは16歳で八歳に拾われ八年、最後の台詞は時間外の手当、など)を、外部の提案で覆さない。
