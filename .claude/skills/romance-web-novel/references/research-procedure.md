**調べたことは、会話に書いて終わりにしない。必ず `data/` に追記する。** 会話はセッションが終わると消える。

## この環境でできること・できないこと

| 手段 | 使えるか | 備考 |
|---|---|---|
| WebSearch | **使える** | 検索結果の要約とURLが返る。要約は検索側のモデルが書くので、数字は複数の結果で照合する |
| WebFetch | **使えない** | 2026-09-27時点、wikipedia.org を含めエグレスで遮断される |
| curl | **使えない** | 同上 |
| Googleドライブ | 使える | 社内資料・中川様が置いた本文テキスト |

**作品の本文はこの環境から読めない。** 本文の分析が要るときは、中川様に貼っていただくか、ドライブに置いていただく。

## 手順

### 1. 何を確かめたいかを1行で書く

例：「女性主人公で男性にも読まれた作品は、恋愛以外に何を軸にしているか」
問いが決まらないまま検索を始めると、要約を集めるだけで終わる。

### 2. 検索は並列で5本ずつ投げる

同じ問いを角度を変えて投げる。
- 作品名＋「男女比」「読者層」
- 作品名＋「累計」「突破」（部数と時点）
- 作品名＋「あらすじ」（軸の確認）
- 市場名＋「年間ランキング 2025」
- 反例を探す検索（「男性誌 女性読者」など、仮説が外れる例）

**反例を必ず1本入れる。** 2026-09-27の調査では、反例（『来世は他人がいい』のアニメ視聴が女性寄り）が一番役に立った。

### 3. 事実と推測を分ける

| 書き方 | 使う場面 |
|---|---|
| 数字＋時点＋出典URL | 事実 |
| 「〜と評されている」＋出典URL | レビュー・論評 |
| 「未確認」 | 探したが見つからなかった |
| 「仮説」 | 事実から自分で導いたこと |

**知恵袋・個人ブログは根拠にしない。** 使うのは出版社・配信会社のプレスリリース、ニュースサイト、調査会社のデータ、公式サイト。

### 4. `data/` に追記する

| ファイル | 何を足すか |
|---|---|
| `data/works.csv` | 調べた作品を1行ずつ。IDは連番（W024から） |
| `data/market-snapshot.md` | 読者の男女比・年代、ランキング、コンテスト日程。**古い数字は消さず、新しい行を上に足す** |

### 5. 原則を足すときは、根拠の強さを書く

`references/crossover.md` などに原則を足すときは、**強い／中／仮説**のどれかを必ず書く。
仮説を事実のように書かない。

### 6. 確認日を入れる

`works.csv` の「確認日」列と、`market-snapshot.md` の「最終更新」を必ず更新する。
ランキングと部数は半年で古くなる。

## 企画の衝突確認（採点の前に必ず）

1. ログラインを「職能 × 関係 × 事件」の3語に縮める（例：代筆 × 女性主人公 × 依頼人の手紙）
2. その3語で検索する。**加えて、2語ずつの組み合わせでも検索する**
3. アニメ・ドラマ化された作品が出たら、衝突「大」
4. 書籍化・コミカライズ済みで核が2つ以上重なれば「中」
5. 見つからなければ「未確認」（「なし」とは書かない）
6. 見つけた作品は `works.csv` に【衝突】とメモして足す

2026-09-27、この手順を飛ばして1軍を決め、後から『ヴァイオレット・エヴァーガーデン』との衝突に気づいた。

## works.csv の列

| 列 | 書き方 |
|---|---|
| 恋愛以外の軸 | 具体的に（「毒と薬の知識で事件を解く」） |
| 軸の型 | `crossover.md` の7型から：謎解き／頭脳戦／勝負／職能／物理／潜入・偽装／経営 |
| 恋愛の濃さ | 主／従／薄 |
| 恋愛の向き | 誰から誰へ。一方通行か双方向か |
| 男性読者の根拠 | 数字があれば数字。なければ「未確認」。反例なら【反例】と頭に付ける |
| 数字の時点 | YYYY-MM |
