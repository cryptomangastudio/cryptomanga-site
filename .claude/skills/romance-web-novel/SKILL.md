# 女性向けWEB小説スキル

`creative-writing` が創作全般の一般論を扱う。こちらは**女性向けWEB小説に限った、出す前の確認手順**を扱う。
両方読む場合は、`creative-writing` → 本スキルの順。本スキルの記述が優先される。

## このスキルが存在する理由

2026年9月の作業で、同じ書き手（Claude）が次の間違いをした。いずれも知識の不足ではなく、**出す前に自分で確かめなかったこと**が原因だった。

| 何をしたか | どう間違っていたか |
|---|---|
| 「毒味役は三年で舌を失う」と書いた | 史実を確認していなかった。そのような記録はない |
| 「味を濃くすれば毒が薄まる」と書いた | 量が変わらないので成り立たない |
| 毒味役だけが慢性中毒になる設定にした | 一膳すべて食べる当主のほうが摂取量が多い |
| 下働きが主人の膳に先に箸をつける設定にした | 身分制度として不自然なのに気づかなかった |
| タイトルを自分で「強い」と判断した | 読んだ側は内容を想像できなかった |
| キャッチフレーズに抽象語だけ並べた | 作品固有の言葉が一つも入っていなかった |
| 説明文の主語と述語がねじれ、体言止めを並べた | 読み手に意味が通じなかった |

同じ間違いを繰り返さないために、確認の手順を文書にした。**手順を飛ばして出してはいけない。**

## 作業の順番

依頼が「企画を作る」に近いほど、この順で進める。

1. **企画の骨組み**（ログライン → ヘイト役と呪縛 → ヒーローの執着の理由 → 接点 → 見せ場6種）
   - **恋愛以外の軸を1つ（多くて2つ）決める。**「バトル」の7型（`references/crossover.md`）から選ぶ
   - A〜Eに加えて**補助軸F（男女両読）**を採点する
2. **設定の検算**（`references/logic-audit.md`）
3. **事実の確認**（`references/fact-check.md`）
4. **タイトルとキャッチの作成と検査**（`references/title-and-catch.md`）
5. **あらすじ**（数行版 → 500字版 → 1,000字版）
6. **30話構成**（冒頭／山場1／山場2／ヒキ）
7. **本文執筆**（ドライブの `21_執筆スタイルガイド` に従う）
8. **日本語の検査**（`references/japanese-quality.md`）
9. **AIらしさの除去**（`creative-writing/references/anti-ai-tells.md`）

2〜4と8は飛ばせない。1で作ったものが2〜4で壊れたら、1に戻る。

## 絶対に守ること

1. **確認していない事実を、事実として書かない。** 調べていないなら「要確認」と明記する
2. **ヒーローの内面を地の文に書かない。** 女性向けの中核は情報の非対称
3. **ヒーローの執着の理由（なぜ彼女でなければならないか）を1文で言えないまま、先に進まない。** 社内基準ではこれが1点以下の企画は打ち切り
4. **タイトルだけを見て内容を言えないなら、そのタイトルは採用しない**
5. **出す前に日本語を検査する**
6. **一発で通すつもりで出す。** 推敲は相手に渡す前に自分で済ませる
7. **作業フォルダをWithLinksのツリーに作らない。** 下の「保存場所」を必ず読む

### フォルダを作る前の確認（省略しない）

1. 親フォルダを `get_file_metadata` で引き、`parentId` を**共有ドライブのIDに当たるまで**たどる
2. 経路に「クリプトマンガスタジオ」（`1ginhyYBQ9bZ90DqFjeZRtwoUAsbSofEZ`）が入っているか確かめる
3. 入っていなければ、そこには作らない
4. 迷ったら `原作スタジオ`（`1c-jN3NcjCZBFHiLToBBP6LO3WuwtaYyO`）の下に作る
5. 「移動しました」「作りました」と報告する前に、**作った場所を上までたどって確かめる。** たどっていない報告はしない
6. 過去に作ってしまったものを見つけたら、報告を待たずに移す
