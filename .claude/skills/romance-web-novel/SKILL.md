# 女性向けWEB小説スキル

`creative-writing` が創作全般の一般論を扱う。こちらは**女性向けWEB小説に限った、出す前の確認手順**を扱う。
両方読む場合は、`creative-writing` → 本スキルの順。本スキルの記述が優先される。

## このスキルが存在する理由

2026年9月の作業で、同じ書き手（Claude）が次の間違いをした。いずれも知識の不足ではなく、**出す前に自分で確かめなかったこと**が原因だった。

| 何をしたか | どう間違っていたか |
|---|---|
| 「毒味役は三年で舌を失う」と書いた | 史実を確認していなかった。そのような記録はない |
| 「味を濃くすれば毒が薄まる」と書いた | 量が変わらないので成り立たない |
| 毒味役だけが慢性中毒になる設定にした | 一膳すべて食べる当主のほうが摂取量が多い |
| 下働きが主人の膳に先に箸をつける設定にした | 身分制度として不自然なのに気づかなかった |
| タイトルを自分で「強い」と判断した | 読んだ側は内容を想像できなかった |
| キャッチフレーズに抽象語だけ並べた | 作品固有の言葉が一つも入っていなかった |
| 説明文の主語と述語がねじれ、体言止めを並べた | 読み手に意味が通じなかった |

同じ間違いを繰り返さないために、確認の手順を文書にした。**手順を飛ばして出してはいけない。**

## 作業の順番

依頼が「企画を作る」に近いほど、この順で進める。

0. **ベンチマークを2作に固める**（`references/benchmarks.md`。構造を借りる1作・棚と情緒を借りる1作。企画ごとに変えない）
1. **企画の骨組み**（ログライン → ヘイト役と呪縛 → ヒーローの執着の理由 → 接点 → 見せ場6種）
   - **恋愛以外の軸を1つ（多くて2つ）決める。**「バトル」の7型（`references/crossover.md`）から選ぶ
   - A〜Eに加えて**補助軸F（男女両読）**を採点する
   - **読者の予想10個を出して避ける**（`references/subvert-expectations.md`）。別の目（別のエージェント）に、骨組みだけ渡して予想させる ── 中川様、2026-09-29
2. **設定の検算**（`references/logic-audit.md`）
3. **事実の確認**（`references/fact-check.md`）
4. **タイトルとキャッチの作成と検査**（`references/title-and-catch.md`）
5. **あらすじ**（**書店員が読んで分かる読み物として書く。字数は500字を超えてよい** ── 中川様、2026-09-28。300字では情報が足りない）
   - 必ず入れる：境遇／発端／毎話の型／恋の進み方（出来事で）／恋の障害／中盤の転換／真相／ざまぁ／結末と二人の着地
   - 書き方は `references/title-and-catch.md` の「全体あらすじの書き方」
6. **イベントマップ**（`references/event-map.md`。作った後に、**予想10個を再度出させ、当たりが減ったか確かめる**。出来事の見出し＋具体的な一場面の2行で書く。感情の山谷と、繰り返し要素のタグを一覧にする ── 中川様、2026-09-29）
7. **30話構成**（`references/thirty-episodes.md`。冒頭／山場／ヒキ。型崩し4種を配置し、予想役と整合性の査読者に通す）。**中川様の許可を得てから進める**
8. **本文執筆**（ドライブの `21_執筆スタイルガイド` に従う）
9. **日本語の検査**（`references/japanese-quality.md`）
10. **AIらしさの除去**（`creative-writing/references/anti-ai-tells.md`）

2〜4と9は飛ばせない。1で作ったものが2〜4で壊れたら、1に戻る。

## 絶対に守ること

1. **確認していない事実を、事実として書かない。** 調べていないなら「要確認」と明記する
2. **ヒーローの内面を地の文に書かない。** 女性向けの中核は情報の非対称
3. **ヒーローの執着の理由（なぜ彼女でなければならないか）を1文で言えないまま、先に進まない。** 社内基準ではこれが1点以下の企画は打ち切り
4. **タイトルだけを見て内容を言えないなら、そのタイトルは採用しない**
5. **出す前に日本語を検査する**
6. **一発で通すつもりで出す。** 推敲は相手に渡す前に自分で済ませる
8. **舞台（年・都市・時代）を、なんとなくで置かない。** 根拠と、現代・SFに移したとき何が崩れるかを書く（`references/house-rubric.md` の2026-09-28の項）
7. **作業フォルダをWithLinksのツリーに作らない。** 下の「保存場所」を必ず読む

## 人物の呼び方（中川様方針、2026-09-28）

**企画の段階では人名を付けない。役名で書く。** 名前は後で決める。
- 主人公の女性は「ヒロイン」、相手役は「ヒーロー」
- その他は「父」「親方」「叔父」「先代」「家令」など役名
- 同じ役名が二人に当たりうるときは、**あらすじ本文では、その都度所有者を書く**（例：「ヒーローの父である先代」「ヒロインの父」）。企画書の冒頭で一度定義しただけでは、初見の読者は迷う。「父」だけで書かない（2026-09-28、中川様の指摘）
- ヒーローの父は「先代」、ヒロインの父は「ヒロインの父」（ヒロイン側の文脈だけなら「亡き父」）と、指し方を固定する

## 専門知識の扱い（中川様方針、2026-09-28）

**調べるのは網羅的に。書くのは雰囲気まで。**
専門性が出ると監修が要り、制作が重くなる。濁すところは濁す。ただし濁すために、作品に必要な知識は網羅的に調べる。

- 作品ごとに「〇〇の知識.md」を作り、各項目に「作中で使う言葉」と「書かないこと」を付ける（例：`drafts/jomae/錠前の知識.md`）
- 書かないこと：部品名、手順、数値、仕組みの説明
- 技は手・耳・目の感覚で書く。専門用語は名前だけ出して説明しない
- 読者が「本当にそうなのか」と気にするほど細部を書かない
