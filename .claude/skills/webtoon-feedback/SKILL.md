# Webtoon原稿PDF フィードバックツール

入力されたPDFをページ画像に変換して視覚レビューし、WithLinksの監修基準・FB文体で
フィードバックレポートを生成する。

## 前提

- Google Drive MCPツールが使えるセッションではDrive上のPDFを直接取り込める
- PyMuPDFが必要: `pip install pymupdf`(未インストールなら最初に実行)
- 作業ファイルはすべてscratchpadディレクトリに置く(リポジトリを汚さない)

## ワークフロー

### 1. PDFを取得する

- **ローカルパス/添付**: そのまま使う
- **Drive上のファイル**: `mcp__Google_Drive__search_files` で `title contains '<ファイル名>'` を検索し、
  `mcp__Google_Drive__download_file_content` でダウンロードする。
  結果が大きい場合はツール結果がJSONファイルに保存されるので、以下でデコードする:
  ```bash
  jq -r '.content' <保存されたツール結果ファイル> | base64 -d > <scratchpad>/genko.pdf
  ```
- ファイル名が曖昧な場合は候補を列挙してユーザーに確認する

### 2. 工程と作品を判定する

ファイル名の命名規則 `作品名_工程_話数_●稿` から作品・工程(ネーム/線画/背景/仕上げ)・話数を読み取る。
不明なら1ページ目を見て判定する(`references/other-stages.md` の判定基準参照)。

### 3. ページ画像に変換する

```bash
python3 <このスキルのdir>/scripts/pdf_to_pages.py <scratchpad>/genko.pdf <scratchpad>/pages
```

縦長ページは自動でオーバーラップ付きタイル(`page003_t01.png`...)に分割される。
出力されたマニフェスト(ページ→画像対応表)を控える。

### 4. チェックリストを読み込む

- 仕上げ原稿 → `references/finish-checklist.md`
- ネーム/線画/背景 → `references/other-stages.md`
- 文体・フォーマット → `references/fb-style-guide.md`(工程を問わず必読)

### 5. 全ページを視覚レビューする

- Readツールで**全ページ画像を順に見る**(飛ばさない。タイル分割されたページは全タイルを見る)
- チェックリストの観点で問題を拾い、ページ番号・コマ位置をメモする
- 前後のページと比較が必要な観点(同ポーズ連続・色の競合・動線)は行き来して確認する
- ページ数が多い場合(30ページ超)はAgentツールで数ページずつ並行レビューしてもよいが、
  最終的な取捨選択と文体統一は自分で行う

### 6. FBレポートを生成する

`references/fb-style-guide.md` のフォーマットに従い、
`<scratchpad>/<作品名>_<工程>_<話数>_FBレポート.md` を作成:

1. **総評**: 良い点2〜3個 → 全体傾向
2. **FB一覧**(ページ順): `【P● / ●コマ目】■修正依頼|■相談|■参考(カテゴリ)` + 本文
3. **申し送り事項**: 当該工程では直せない他工程起因の問題
4. **チェックリスト通過状況**: 観点ごとに ✅/⚠️ の一覧

件数を水増ししない。問題のない観点は「問題なし」と明記する。

### 7. 出力する

- `SendUserFile` でレポートを送る(display: attach)
- チャットには修正依頼・相談の件数と重要トップ3だけ要約する
- 求められたらpptxスキルでFBスライド(該当ページ画像+コメント)版も作成できる

## 精度向上(任意)

同作品の過去話のFBスライドがDriveにあれば1〜2件読み、その作品固有の頻出指摘
(キャラの色味・演出方針など)を反映する。検索例:
`(title contains 'FB' or title contains '監修') and title contains '<作品名>'`

## 注意

- FBの元データ(WithLinksのマニュアル・FBスライド)は社外秘。レポートに原文を長く引用しない
- 生成したFBはあくまでドラフト。クリエイターに送る前に監修者が必ず目を通す前提で作る
- 判断に迷う指摘は温度感を「■相談」に落とす(誤検出で修正依頼を出すより安全)
