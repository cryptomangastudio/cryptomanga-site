# Webtoon原稿PDF チェック/校閲ツール

入力されたPDFをページ画像に変換して視覚レビューし、選択されたモードの観点・文体でレポートを生成する。

## モード一覧

| モード | 種別 | 観点ファイル | 見るもの |
|---|---|---|---|
| ネームチェック | 監修FB | `references/check-name.md` | コマの流れ・演技・構成 |
| 線画チェック | 監修FB | `references/check-senga.md` | 表情・演技・画面の質 |
| 背景チェック | 監修FB | `references/check-haikei.md` | 場所の伝達・動線・情報量 |
| 着彩チェック | 監修FB | `references/check-chakusai.md` | 色設計・塗り・設定との一致 |
| 仕上げチェック | 監修FB | `references/check-shiage.md` | 色味・影・装飾・演出 |
| 線画校閲 | 校閲 | `references/kouetsu-common.md` + `references/kouetsu-senga.md` | 左右反転・衣装揺れ・ネーム相違 |
| 仕上げ校閲 | 校閲 | `references/kouetsu-common.md` + `references/kouetsu-shiage.md` | シームレス・マスク・文字まわり |

**監修FBと校閲は別物**(混ぜない):
- **チェック(監修FB)** = クオリティ面の演出提案。文体は `references/fb-style-guide.md`(■修正依頼/■相談/■参考)
- **校閲** = 間違い探し。クオリティに触れない。書き方は `references/kouetsu-common.md`(■指摘/■要確認/■申し送り)

## ワークフロー

### 1. モードを決める(ボタン)

1. ユーザーの発言か依頼文でモードが特定できればそれを使う
2. 特定できなければファイル名 `作品名_工程_話数_稿数` の工程から候補を絞り、
   **AskUserQuestionで必ず確認する**。質問は2つ:
   - 「種別は?」→ チェック(監修FB) / 校閲
   - 「工程は?」→ 背景 / 線画 / 着彩 / 仕上げ (ネームはOtherで自由入力)
   ファイル名から工程が明らかな場合は種別の質問だけでよい。
3. AskUserQuestionが使えない状況(非対話実行)では、ファイル名から推定したモードで進め、
   レポート冒頭に「◯◯モードで実行(変更したい場合はモード名を指定して再依頼)」と明記する
4. 校閲はネーム/線画/仕上げの3工程のみ(背景・着彩の校閲依頼が来たら、校閲は3工程である旨を伝えて確認する)

### 2. PDFを取得する

- **ローカルパス/添付**: そのまま使う
- **Drive上のファイル**: Drive MCPの `search_files` で `title contains '<ファイル名>'` を検索し、
  `download_file_content` でダウンロードする。結果が大きい場合はツール結果がJSONファイルに
  保存されるので、以下でデコードする:
  ```bash
  jq -r '.content' <保存されたツール結果ファイル> | base64 -d > <scratchpad>/genko.pdf
  ```
- ファイル名が曖昧な場合は候補を列挙してユーザーに確認する

### 3. ページ画像に変換する

```bash
pip install pymupdf  # 未インストール時のみ
python3 <このスキルのdir>/scripts/pdf_to_pages.py <scratchpad>/genko.pdf <scratchpad>/pages
```

縦長ページは自動でオーバーラップ付きタイル(`page003_t01.png`...)に分割される。
出力されたマニフェスト(ページ→画像対応表)を控える。

### 4. 観点ファイルを読み込む

モード一覧の該当ファイルを読む。校閲モードは `kouetsu-common.md` を必ず先に読む。

### 5. 補助資料を取り込む(あれば)

- **校閲・ネーム相違チェックには比較対象が要る**: 線画校閲・仕上げ校閲では同話数のネームPDF、
  衣装確認では前話の原稿やキャラデザがDriveにあれば取得して並べて確認する。
  見つからなければ「ネーム比較・前話比較は未実施」とレポートに明記する
- 同作品の過去話のFB/校閲スライドがあれば1〜2件読み、作品固有の頻出指摘・作品別表記ルール
  (例: 「こと」をひらがな等)を反映する。検索例:
  `title contains '<作品名>' and (title contains 'FB' or title contains '監修' or title contains '校閲')`

### 6. 全ページを視覚レビューする

- Readツールで**全ページ画像を順に見る**(飛ばさない。タイル分割されたページは全タイルを見る)
- モードの観点で問題を拾い、ページ番号・コマ位置をメモする
- 前後の比較が必要な観点(同ポーズ連続・衣装揺れ・シームレス・動線)は行き来して確認する。
  特に仕上げ校閲のシームレスは、隣接タイル/ページの境界を連続で見る
- ページ数が多い場合(30ページ超)はAgentツールで数ページずつ並行レビューしてもよいが、
  最終的な取捨選択と文体統一は自分で行う

### 7. レポートを生成する

`<scratchpad>/<作品名>_<工程>_<話数>_<モード名>レポート.md` を作成:

**チェック(監修FB)モード** — `fb-style-guide.md` のフォーマット:
1. 総評(良い点2〜3個→全体傾向)
2. FB一覧(ページ順): `【P● / ●コマ目】■修正依頼|■相談|■参考(カテゴリ)` + 本文
3. 申し送り事項(他工程起因の問題)
4. チェックリスト通過状況(✅/⚠️)

**校閲モード** — `kouetsu-common.md` の書き方:
1. 実行条件(比較したネーム・前話資料の有無)
2. 指摘一覧(ページ順): `【P● / ●コマ目】■指摘|■要確認(カテゴリ)` + 事実ベースの短文
3. 申し送り(クオリティ面で気になったもの、最大1〜2件)
4. クリスタ上で要確認の項目(PDFでは判定できないもの)
5. チェックリスト通過状況(✅/⚠️)

件数を水増ししない。問題のない観点は「問題なし」と明記する。

### 8. 出力する

- `SendUserFile` でレポートを送る(display: attach)
- チャットには件数と重要トップ3だけ要約する
- 求められたらpptxスキルでFBスライド(該当ページ画像+コメント)版も作成できる

## 注意

- 元データ(WithLinksのマニュアル・FB/校閲スライド)は社外秘。レポートに原文を長く引用しない
- 生成したレポートはドラフト。クリエイターに送る前に監修者/校閲者が必ず目を通す前提で作る
- 監修FBで判断に迷う指摘は「■相談」に、校閲で断定できない指摘は「■要確認」に落とす
