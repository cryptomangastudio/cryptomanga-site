# WithLinks流フィードバックの書き方

過去のFBスライド(仕上げFB・線画FB・背景FB・ネームFB)から抽出した、実際の言い回しと運用ルール。
チェック(監修FB)系モードで生成するFBは必ずこのスタイルに合わせる。
※校閲系モードのコメントの書き方は `kouetsu-common.md` を参照(温度感タグも異なる)。

## 基本フォーマット

1件のFBは以下の構成:

```
【P3 / 12コマ目】■修正依頼(色味)
セリフ/吹き出しを、暖色(オレンジ系など)に変更お願いします。
もう少し彩度を上げて明るい印象にさせたいです。
```

- 位置は「●P」「●コマ目」で必ず特定する(例: 3P、20コマ目、48,49コマ)
- 1件1論点。理由(なぜ直すか)を添えると通りが良い
- 具体的な対応案を1つ以上添える(「アングルを移動するなど」「薄くするか、模様を一部排除するなど」)

## 温度感は3段階で明示する

実際のFBデータでは、依頼の強さを明確に区別している。必ずどれかを付ける。

| 温度感 | 意味 | 実例の言い回し |
|---|---|---|
| ■修正依頼 | 必ず直してほしい | 「赤枠箇所の調整をお願いします」「恐れ入りますが、ペンで自然になるよう加筆していただくことは可能でしょうか」 |
| ■相談 | 直せれば直してほしい/提案 | 「相談レベルですので、調整できれば程度で大丈夫です」「〜の方がシーンに合いそうかと思ったのですが、如何でしょうか?」 |
| ■参考 | 今後の参考。今回は対応不要 | 「今後のご参考にしていただき、一度ご放念いただき大丈夫です」 |

## 言い回しの型(頻出パターン)

- クッション言葉から入る: 「大変恐れ入りますが」「申し訳ございません」「お手数ですが」
- 依頼形: 「〜していただけますと助かります」「〜お願いします」「〜していただくことは可能でしょうか」
- 提案形(相談): 「〜は如何でしょうか?」「〜かな?と思いましたが如何でしょうか?」
- 自信のない推測は正直に: 「(間違っていたらすいません)」「〜の問題かもしれません」
- 良い点は先に認める: 「今のままでも十分なのですが」「現状でも〜としてまとまっているので」
- 自分側のミスは謝る: 「ネーム時に気づけずすみません」

## やってはいけないこと

- 位置指定なしの漠然としたFB(「全体的に暗い」だけ等)
- 高圧的・断定的な言い方(必ず依頼形・相談形にする)
- 仕上げ担当の責任範囲外(線画・背景・ネーム起因)の問題を修正依頼にする → 「申し送り」として区別する
- 1件に複数論点を詰め込む

## 成果物の形式

- Markdownレポート: `<作品名>_<工程>_<話数>_FBレポート.md` をscratchpadに作成しSendUserFileで送る
- 構成: ①総評(良い点2〜3個→全体傾向) ②ページ順のFB一覧(温度感タグ付き) ③申し送り事項 ④チェックリスト通過状況
- 件数の目安: 実データでは1話あたり修正依頼3〜6件+相談1〜3件程度。粗探しで水増ししない。
  問題がなければ「問題なし」と書く勇気を持つ
