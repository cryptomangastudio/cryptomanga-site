# 配布01 投稿設計 — 脱AI文体チェックリストの配り方

> 〔2026-07〕`配布01_脱AI文体チェックリスト_v1.md`(承認済み)を配るための投稿設計。
> 方針は `../docs/01`、根拠は `../research/02〜04` と `../tracker/観測ログ.md`。

## 受け取り条件 〔推奨: ハードル最小型〕

**必須はコメントのみ。フォローもリポストも条件にしない。**

```
必須: この投稿に「文体」とコメント → 返信でURLを送ります
任意: 更新版も受け取りたい人はフォローだけしておいてください
```

### なぜ条件を盛らないか

| 論点 | 条件を盛る場合(界隈の標準) | 条件を最小にする場合(推奨) |
|---|---|---|
| フォロワー増 | 多い。ただし**配布目的のフォロワーは剥がれる**(research/02失敗1) | 少ないが、内容で納得した人だけが残る |
| 参加数 | 手順が多いほど脱落 | 最大化。**コメント数=Threadsの最重要拡散シグナル**(research/04) |
| ブランド | 煽り界隈と同じ見た目になる | 「条件を付けない人」として界隈で目立つ |

つくるの軸は「同じ一人が全部欲しがる実用物を配る人」。フォロワー数は副指標(`docs/01`)なので、
**条件を盛ってフォロワーを買いに行くより、コメント数を最大化して拡散とリストの入口を広げる方が方針と一致する**。

※検証したい場合は、第2弾(ネタ管理DB)で「フォロー+コメント」条件にして受け取り数を比較する。
1回の配布で条件を変えて比較はできないので、配布ごとに1条件だけ変える。

## Threads投稿文(本命)

> 注意: 本文に外部リンクを貼るとリーチが1/2〜1/4に落ちる(research/04)。**URLは返信で送る**。
> 【要確認】冒頭の「6冊」は実際の刊行状況に合わせて要修正(未刊なら「本を作る中で」等に)。

```
AIで下書きを作ると、だいたい3行で気づかれます。「これ、AIだな」と。

気づかれた瞬間、書いてある中身が正しくても読み飛ばされる。ここが一番きつい。

本を6冊作る間、編集のたびにその「AIっぽさ」の正体を1つずつ潰してきました。
潰した数が26個になったので、チェックリストにまとめました。

A 言い回し
・本音の前に「正直に言うと」と合図を打っていないか
・「本質」「まさに」「〜と言えるでしょう」を乱発していないか
・「〜ですよね?」と読者の感情を指定していないか
ほか2項目

B リズム
・全文が同じ心地よいリズムになっていないか
・「A。B、C、Dも。」の3拍子羅列が続いていないか
・短文ぶつ切りを連発していないか
ほか2項目

C 構成
・「実績→挫折→共感」の黄金テンプレになっていないか
・締めが「ドヤ顔の総括+次回予告」になっていないか
ほか3項目

D 体温(いちばん効きます)
・「絶望した」で終わらせず、その時の身体と手元を書いているか
・比喩が「奈落の底」みたいな劇画調になっていないか
・成功談がトントン拍子になっていないか(冷や汗が抜けていないか)
ほか3項目

E 信頼
・自分がやっていないことをノウハウとして語っていないか
・データを講義にしていないか。逆にぼかしすぎていないか
ほか2項目

26項目全部と、そのまま使えるリライトプロンプトを3本つけました。
番人プロンプトは、この26項目を基準に自分の文章を採点させるやつです。

コメントに「文体」と書いてくれたら、返信でURLを送ります。
更新版も要る人だけフォローしておいてください。新しいAI臭を見つけるたびに足しています。
```

### 設計意図(なぜこの書き方か)

- **中身を全項目列挙**して見せ切る(観測ログ3: 具体的に見せるほど受け取り率が上がる)
- **煽らない**: 締切なし・収益自慢なし・「消します」なし。界隈の標準と逆を行くのが差別化(観測ログ6)
- **投稿自体が26項目に違反していない**こと。これが最大の証明になる。3拍子の羅列を避け、一文の長さを不均一に、締めをドヤ総括にしない
- 末尾は問いではなく事実で終える。返信を無理に誘導しない(誘導しなくてもコメント条件で返信は発生する)

## X版(同時投稿・チャネル比較用)

Xは長文が読まれにくいので**要点+項目数**に圧縮し、リプ欄に全項目をぶら下げる。
本文にURLを置いてよい(Xはリンクでリーチが落ちる度合いがThreadsほど強くない)が、
**チャネル比較のため受け取り経路は同じ「コメント→返信」に揃える**。条件が違うと比較にならない。

```
AIで下書きを作ると、だいたい3行で気づかれます。「これ、AIだな」と。

本を作る間、編集のたびに「AIっぽさ」の正体を潰してきました。26個になったので
チェックリストにしました。リライトプロンプト3本つき。

コメントに「文体」と書いてくれたら返信でURLを送ります。

(全26項目はリプ欄に)
```

## 配布物の置き場所

- Notion公開ページ(複製可)。PDFは後工程 — **まずNotionだけで出す**。PDF待ちで公開を遅らせない
- ページ末尾に、次の配布物(第2弾ネタ管理DB)の予告を1行だけ置く。ここが拡散層→顧客層の入口になる
- **リスト登録は求めない**(浅い配布のため)。LINE/メールの用意は第2弾までに準備すればよい

## 測定 〔`docs/01`のガードレール〕

| 指標 | 記録先 | 見方 |
|---|---|---|
| 主: 受け取り数(コメント数) | `../tracker/配布実績.md` | **インプの0.4%が目安**(観測ログ2)。1万インプで40人前後なら想定内 |
| 副1: インプレッション | 同上 | 入口の太さ。**主指標にしない** |
| 副2: フォロワー増 | 同上 | 条件にしていないので、増えたぶんは質が高いはず |
| 副3: Threads/X別の受け取り数 | 同上 | どちらが主戦場かを数字で決める。感覚で乗り換えない |

**停止ライン**: 拡散(インプ)は出るのに受け取りが0.1%を大きく下回る場合、配布物ではなく
「見せ方」の問題(中身の列挙が足りない/訴求がズレている)を疑って投稿文を作り直す。配布物自体はまだ捨てない。
