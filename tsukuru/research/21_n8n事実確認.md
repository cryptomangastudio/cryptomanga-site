# 21 n8n事実確認 — 戦略推敲(docs/04)の裏取り(2026-07 Web調査)

## A. 導入コスト

- **n8n Cloudに恒久無料プランは無い**(14日トライアルのみ)。Starter $24/月(2,500実行)
- セルフホストは**月800円前後**(Hostinger 24ヶ月契約779円等)だが**Dockerの壁が実在**。競合のしまゆず氏本人が「セルフホスティングに苦労した」記事を公開。三大つまずき=Docker・データ消失・アップデート
- 共用レンタルサーバー(ロリポップ等)での動作事例はゼロ(実質不可と推定)

## B. Threads API

- **n8nにThreads公式ノードは無い**→HTTP Request直叩き(Meta仕様変更リスクを配布者が背負う)
- 自分のアカウントへの投稿ならMeta審査不要。初期設定は10〜15分で、**日本語の無料手順記事が既に飽和**(note に5本以上)
- **本当の壁は「60日で失効するトークン」**。自動更新の仕組みを組まないと止まる。ここが複数記事で最大の壁と指摘
- → テンプレの価値=初期設定ではなく**「止まらない仕組み(トークン自動更新内蔵)+止まった時のリカバリ」**

## C. Creator Hub

- 審査は「数日」〜「**数ヶ月塩漬け**」まで分散。AI一次審査が導入され、それ自体が数日詰まる報告。却下時に修正案なしの事例も
- **日本人の承認実例は複数あり「国内30名弱の公認クリエイター」**という記述(=希少だが取得可能で、既に肩書き商売に使われている)
- 公式ライブラリ経由の直接収益は実質Cloudアフィリエイトのみとの分析。物販はGumroad等外部が主流

## D. 保守負担

- **2025年12月にn8n 2.0がリリースされ破壊的変更多数**(Startノード廃止等)。マイナー更新でもHTTP Requestノードが壊れた事例
- テンプレが壊れる要因は n8n本体×外部API(Meta) の**二重構造**
- → 「買い切り無保証」か「メンバーシップで更新版配布」かの選択が事業設計の核。移行期は「2.0対応済み」表記が短期の差別化になる

## E. 学習者の生息地

- **noteが最も濃い**(テンプレ配布・手順書・メンバーシップが既に定着)。Zenn/Qiitaはエンジニア寄り、YouTubeは発展途上
- n8nは公式日本語UIが無い=言語障壁が「日本語解説」需要の源泉
- 日本語の公式ユーザー会・勉強会は無し

## F. 同時期参入者

- **「Claude Code×n8n×note/Threads自動化」のコンセプトは既に最低3者が先行**(脱・属人チャンネル/そう/しまゆず)。しまゆず氏はメンバーシップ収益化まで到達。テンプレ販売ノウハウ自体もタナベ氏が公開済み
- → **コンセプト単体では差別化不能。**ツール解説(n8nがわかる)でなく成果(発信が回る)側で立つ必要

## 設計を変えるべき事実(6つ)→ docs/04 §4に反映

1. 「無料で始められる」訴求は使えない(Cloud無料廃止)
2. Threadsテンプレの価値の芯は「トークン自動更新」
3. 保守は二重構造 → 更新配布の仕組み(メンバーシップ型)を前提に
4. Creator Hubバッジをローンチ条件にしない(塩漬けリスク)
5. コンセプト重複 → ターゲットと思想で絞る(半自動×書いて売る個人)
6. n8n 2.0移行期は「2.0対応済み」が短期差別化
